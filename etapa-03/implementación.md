El pasaje desde el modelo lógico representado en el diagrama entidad-relación hacia la implementación en el SGBD corresponde a la fase de diseño físico. En esta etapa, los conceptos abstractos del esquema se traducen a estructuras concretas mediante el Lenguaje de Definición de Datos en SQL. Cada entidad del diagrama se transforma en una tabla física en la base de datos, asignando a cada uno de sus atributos un tipo de dato adecuado para el motor del SGBD, tales como cadenas de caracteres para nombres y direcciones, números enteros para identificadores, valores decimales para montos monetarios, y formatos específicos para fechas y horas.
Para mantener la consistencia y la coherencia de la información, en la base de datos física se declaran formalmente las claves primarias que identifican unívocamente a cada registro, así como las claves foráneas que materializan las relaciones lógicas entre las tablas. Estas claves foráneas permiten definir políticas de integridad referencial, como la actualización y eliminación en cascada entre entidades vinculadas. Asimismo, durante la creación física en el SGBD se incorporan restricciones de validación que aseguran que los datos cumplan con reglas de negocio específicas, impidiendo por ejemplo el ingreso de valores negativos en campos de stock o montos, y restringiendo ciertos campos a valores predefinidos.
La ejecución de este proceso dentro del SGBD requiere respetar un orden de jerarquía estricto en el código, donde primero se crean las tablas independientes y principales, luego las tablas derivadas o especializadas, y finalmente las tablas relacionales y transaccionales que dependen de claves foráneas preexistentes. Una vez compilada con éxito la estructura física en el gestor, la base de datos queda completamente preparada para la carga de información mediante sentencias de inserción y para la posterior consulta y manipulación de los datos a través de sentencias SQL.
